# Bulk Listing Signed Upload Design

## Goal

Remove large image bodies from Vercel application routes. Sellers upload images directly from the browser to Supabase Storage, then OSUTrade sends only validated object paths to the AI draft endpoint. This prevents Vercel's request-body limit from blocking multi-image draft generation.

## Chosen Approach

Use short-lived Supabase signed upload tokens. An authenticated OSUTrade route validates image metadata, creates owner-scoped object paths in the existing public `product-images` bucket, and returns upload tokens. The browser uploads each file directly to Supabase with those tokens.

This approach was selected over:

- Posting files through Vercel, which keeps the current payload-limit failure.
- Giving browser clients general Storage insert permission, which expands the RLS and abuse surface.
- Sending Base64 images to OpenAI, which increases payload size and duplicates uploaded bytes.

## Data Flow

1. The seller selects 1-10 JPG, PNG, or WebP files, each no larger than 5 MB.
2. The browser posts only file name, MIME type, and byte size to `/api/products/images/sign`.
3. The authenticated server validates the metadata and creates signed upload tokens for paths under `<user-id>/...`.
4. The browser uploads files directly to Supabase Storage with `uploadToSignedUrl`.
5. The browser posts `{ imagePaths: string[] }` to `/api/products/bulk-drafts`.
6. The server verifies every path belongs to the signed-in user, derives trusted public URLs from the configured bucket, and sends those URLs to the OpenAI Responses API as `input_image` items.
7. AI drafts retain image indexes. Publishing reuses the already uploaded public URLs instead of uploading the files again.

The same direct-upload helper will be used by the manual listing form so its three-image upload cannot hit the same Vercel limit.

## Security Boundaries

- The service-role key stays server-only.
- The browser receives time-limited upload tokens, never the service-role key.
- Object paths are generated by the server and are prefixed with the authenticated user ID.
- The AI route accepts Storage paths, not arbitrary external URLs, preventing callers from making OpenAI fetch attacker-selected hosts.
- Cleanup only removes paths owned by the authenticated user.
- Existing product reads continue using public Storage URLs from the existing `product-images` bucket.

## Error Handling

- Metadata validation returns stable 4xx JSON messages before signed URLs are created.
- A failed direct upload reports which image failed and does not call OpenAI.
- OpenAI failures are logged server-side with HTTP status and provider request ID, while the browser receives a safe, actionable 502 message.
- Non-JSON platform responses are converted by the client into messages containing the HTTP status, avoiding the current generic failure.
- Uploaded files remain available for retry. Explicit clear or photo replacement triggers best-effort cleanup of uncommitted paths.

## Lifecycle And Cleanup

Uploaded files become final listing images when a product is successfully created. The client tracks committed paths and never deletes them. Explicit clear, file replacement, and failed pre-publish flows remove only uncommitted owner-scoped paths. Closing a tab can still leave an orphaned object; automatic age-based cleanup is intentionally deferred because it requires a scheduled server job and separate retention policy.

## Compatibility

- No database schema migration is required.
- The existing `product-images` bucket must remain public and configured.
- Existing product records keep the same `imageUrl` and `imageUrls` shape.
- The existing `/api/products/images` multipart route remains available for compatibility, but the sell page no longer depends on it.

## Verification

- Unit tests cover metadata validation, owner-scoped paths, JSON-only draft payloads, URL generation, upload failure messages, and cleanup filtering.
- Existing AI response parsing and stale-request protections remain covered.
- Full Vitest, TypeScript, production build, and diff checks must pass.
- A browser smoke test verifies manual and AI modes no longer post image files to Vercel routes.
